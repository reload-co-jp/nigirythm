就職活動の面接で「自己PRをお願いします」と言われる。企業のPR部が新商品の発表会を準備する。ソフトウェア開発のチャットでは「PR出したのでレビューお願いします」というメッセージが飛び交う。三つの場面に出てくる「<WordLink slug="pr">PR</WordLink>」は、同じ2文字でありながら、指しているものがまるで違う。

## 広報としてのPR

いちばん古くからあるのは、英語 public relations の頭文字としてのPRだ。国語辞典は、官公庁や団体、企業が施策や事業内容などについて「大衆の理解と協力を求めるために、各種の媒体を通じて広く知らせること」と説明し、「広報」という訳語を当てている<Ref id="kb-pr" />。

米国パブリック・リレーションズ協会（PRSA）は、この実践が20世紀初頭にさかのぼるとしたうえで、定義そのものが時代とともに変わってきたと述べる。初期の定義は報道対応や宣伝（publicity）を重視していたが、近年は「関係構築」に重心が移った。PRSAが現在掲げる定義は「組織とその公衆とのあいだに、相互に有益な関係を築く戦略的コミュニケーションのプロセス」である<Ref id="prsa-about" />。

## 「自己PR」への広がり

ところが日本語のPRは、組織の広報にとどまらなかった。同じ辞典は広報の語義に続けて「また、一般に、長所・美点を宣伝すること」と記している<Ref id="kb-pr" />。「自己PR」や「地元の魅力をPRする」は、この広がった意味での用法だ。

PRSAの定義が「関係」を重視する方向に進んだのに対し、日本語の日常語としてのPRは「売り込む」方向に意味を広げた、と対比することもできる。ただし、日本語でこの拡張がいつ、どのように進んだのかは、まだ確かな資料にたどり着けていない。ここでは「辞書に両方の語義が載っている」という事実までにとどめておく。

## プルリクエストとしてのPR

一方、ソフトウェア開発者にとってのPRは、まったく別の語句の略である。GitHubのドキュメントは pull request を「コード変更をプロジェクトにマージするための提案」と説明し、変更を反映する前に議論やレビューを行うための中心的な機能と位置づけている<Ref id="gh-docs-pr" />。

pull は、他のリポジトリの変更を自分の側へ「引き込む」Gitの操作を指す。Git本体には git request-pull というコマンドがあり、自分の公開リポジトリから変更を pull してもらうための依頼文を上流のプロジェクト向けに生成する<Ref id="git-request-pull" />。「pull してほしいという request」という発想そのものは、GitHub以前のGitの作法にも見て取れる。もっとも、GitHubの「pull request」という呼称がこのコマンドから直接採られたのかどうかは、本サイトでは確認できていない。

## 同じ形、別々の語句

広報のPRと、プルリクエストのPRのあいだに、歴史的なつながりはない。public relations と pull request という別々の英語が、頭文字にした結果たまたま同じ2文字になった。これは「略語の衝突」と呼ぶべきケースで、意味が枝分かれしたのではなく、別の根から伸びた言葉が同じ場所で交差している。

衝突が実害を生むことは少ない。会話の文脈が、どちらのPRかを自然に決めてくれるからだ。それでも、広報担当者とエンジニアが同じ会議室にいるとき、「PRの件ですが」という一言は、ほんの一瞬、二通りに聞こえるかもしれない。
